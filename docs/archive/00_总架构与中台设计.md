# AI Game Lab：AI 游戏研发实验平台总设计

## 1. 项目定位

构建一套以 DeepSeek 为推理引擎、Tool Calling 为执行能力、中台为观测与控制中心的 AI 游戏研发实验平台。

核心目标：
- AI 不只回答问题，而是能够调用真实工具执行任务。
- 所有 Agent 决策、工具调用、实验结果、代码修改和测试结果可追踪。
- 支持单 Agent 与多 Agent 协作。
- 支持游戏设计、数值模拟、自动测试、研究、自动开发五类能力。
- 人类负责目标、约束、审批和最终判断。

第一实验项目建议使用 PROJECT ORBITAL，但平台不能与具体游戏强耦合。

## 2. 总体架构

```text
                         Web 中台
              Dashboard / Agent / 实验 / 数据 / 日志
                              │
                    AI Orchestrator
             任务调度 / Agent 状态机 / 审批 / 重试
                              │
       ┌──────────────────────┼──────────────────────┐
       │                      │                      │
 Game Designer          Game Tester            Researcher
       │                      │                      │
       └──────────────────────┼──────────────────────┘
                              │
                         Tool Registry
               文件 / 代码 / 模拟 / 数值 / Git / Web
                              │
            ┌─────────────────┼──────────────────┐
            │                 │                  │
        Game Runtime       Simulator         Repository
            │                 │                  │
            └─────────────────┼──────────────────┘
                              │
                    Event / Metrics Layer
                              │
                  PostgreSQL + Redis + Files
```

## 3. 推荐技术栈

### 后端
- Java 21
- Spring Boot 3.x
- PostgreSQL
- Redis
- SSE / WebSocket
- Docker

### 前端
- React
- TypeScript
- Vite
- ECharts
- Monaco Editor

### AI
统一建立 `LLM Gateway`，第一阶段接 DeepSeek。

Gateway 统一处理：
- API Key
- Model routing
- Streaming
- Tool Calling
- Structured Output
- Retry
- Timeout
- Token usage
- Cache usage
- Error handling

Agent 禁止直接散落调用 DeepSeek API。

- prompt

- errors
- final result

- experimentId
- configVersion
- seed
- simulationCount
- scenario
- result

## 6. 中台功能

### Dashboard
显示：
- 当前运行 Agent
- 今日任务数
- 成功率
- 平均 Run 时间
- Tool 调用次数
- Token 消耗
- Cache 命中率
- 模拟次数
- 测试通过率
- 最近异常

### Agent Monitor
显示：
- Agent 状态
- 当前任务
- 当前 Step
- 最近 Tool Call
- Tool 耗时
- Token
- 错误
- 是否等待人工审批

### Run Trace
```text
Run
 ├─ Step 1
 │   └─ tool:get_game_config
 ├─ Step 2
 │   └─ tool:simulate_game
 ├─ Step 3
 │   └─ tool:modify_config
 └─ Step 4
     └─ final
```

不要向用户展示模型隐藏思维链。只展示决策摘要、工具轨迹、输入输出和可审计事件。

### Experiment Center
支持实验对比：
- DPS
- TTK
- Win Rate
- Death Time
- Upgrade Pick Rate
- Build Distribution
- Difficulty Curve

### Artifact Center
归档：
- 设计文档
- JSON / CSV
- 截图
- 测试报告
- Patch
- Git Commit
- Build Artifact

## 8. Human-in-the-loop

```text
Agent
 ↓
Action Proposal
 ↓
中台
 ↓
Approve / Reject
 ↓
Tool Executor
```

例如 AI 要把暴击倍率从 2.0 修改为 1.7，必须展示 diff、理由、实验依据，然后等待批准。

## 9. Agent 状态机

```text
PENDING → RUNNING → COMPLETED
             │
             └→ WAITING_APPROVAL → RUNNING

任何状态 → FAILED → RETRY / CANCEL
```

必须限制：
- 最大 Step
- 最大 Token
- 最大运行时间
- 最大 Tool Call
- 最大重试次数

## 10. 第一阶段 MVP

## 11. 成功标准

给 AI 一个目标后，它能够在权限约束内自主调用工具、执行、验证、迭代；人类能够从中台观察、批准、拒绝、暂停和恢复整个过程。
