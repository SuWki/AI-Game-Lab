# AI Game QA Team 设计文档

> 2026-11-12 范围与状态说明：本文为概念归档，当前 QA 设计入口见 [QA 模块](../projects/04_AI_Game_Agent_Team/README.md)。不能将示例阈值直接用于所有游戏或把缺证据默认为通过。

## 1. 目标

建立多 Agent 游戏测试团队，由 QA Lead 统一协调。

成员：
- QA Lead
- Player Agent
- Combat Analyst
- Numerical Analyst
- Exploit Hunter
- UX Reviewer
- Release Manager

## 2. 协作
```text
                  QA Lead
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
    Player        Numeric       Exploit
     Agent         Agent          Agent
       │             │             │
       └─────────────┼─────────────┘
                     ↓
               Combat Analyst
                     ↓
                  QA Lead
                     ↓
              Release Manager
```

## 3. Player Agent
关注真实玩家行为：
- 新手
- 激进
- 保守
- 随机
- Build 专精

## 4. Numerical Analyst
检查：
- DPS
- TTK
- 收益曲线
- 成长曲线
- 属性相关性
- Build 强度
- 经济系统

输出必须引用实验数据。

## 5. Exploit Hunter
主动寻找：
- 无限收益
- 无限资源
- 无敌
- 卡死
- 重复触发
- 负数
- NaN
- 浮点异常
- 边界条件漏洞

## 6. Combat Analyst
关注：
- 战斗节奏
- 敌人压力
- 玩家操作空间
- 关卡难度
- Boss
- Build 克制关系

## 7. UX Reviewer
关注：
- 玩家是否理解规则
- 升级是否清晰
- 信息是否足够
- UI 是否误导
- 反馈是否及时

## 8. QA Lead
职责：
1. 分配任务
2. 收集结果
3. 判断冲突
4. 要求补充实验
5. 汇总风险
6. 给出 Release Recommendation

禁止简单多数投票。出现冲突必须通过证据和实验解决。

## 9. Release Gate

```text
PASS
CONDITIONAL_PASS
FAIL
```

阈值配置化，例如：
- Critical Bug > 0 → FAIL
- Soft Lock > 1% → FAIL
- Dominant Build > 50% → FAIL
- Crash Rate > 0.5% → FAIL

## 10. 最终报告
```text
Build Version: v18
总体结论：CONDITIONAL_PASS
Critical: 0
High: 2
Medium: 7
主要问题：...
建议：...
```
