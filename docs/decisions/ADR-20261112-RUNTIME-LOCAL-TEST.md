# ADR：Runtime 协议恢复与真实游戏证据

日期：2026-11-12。状态：按用户“完成 Runtime、真实测试证据、修改回归三批开发”的指令实施。本决策覆盖相同主题的早期完成判定和冻结摘要；不改写历史验收结果。

## 背景与选择

现有 Designer/Tester/Research/QA 共用 Runtime，但原实现没有把工具结果带入下一轮、没有保存整批供应商调用 ID，并将预算耗尽视为完成。本地游戏测试又不属于内置 Java GameConfig，不能伪造 v001 配置归属。

选择继续复用一个 AgentLoop / ToolRegistry / SQLite，追加协议与本地证据表，不创建另一套 Agent 服务或数据库。

## 决定

1. COMPLETED 表示模型正常 stop；截断、预算耗尽、无效循环为 FAILED，时间预算为 TIMEOUT。目标是否被游戏证据证明，仍需独立 QA 判定，模型 stop 本身不是质量通过。
2. PENDING 可取消。终态不可被迟到响应覆盖；重试创建新 Run 并实际入队；同 Run 在单后端进程内串行执行，恢复/审批状态使用数据库条件迁移。
3. 新 Run 固定用户目标、System Prompt 内容与哈希、工具 schema 与白名单、模型、温度、maxTokens 和总时限。完整保存可见 assistant/tool 协议，不保存隐藏推理。按完整工具回合裁剪模型上下文，原始证据继续保留。
4. 整批调用在首次执行前事务保存。QUEUED 可继续执行；STARTED 且结果未知的调用不得盲目重放。旧历史缺少原始协议时明确失败，要求核对后重试。审批决定成为 tool 观察，继续执行批次中剩余调用。
5. 真实本地游戏以 `local-<SHA256>` 标识声明的源码清单，命令与产物指纹独立保存。该命名空间不等于 game_config_version；Finding 校验必须接受已登记的本地版本及对应执行证据。
6. 本地检查只有具备本次 runId、完整覆盖声明、唯一检查 ID 与明确 PASS/FAIL 时才参与 QA/导入/修改回归。通过报告缺少基线检查时为 INCONCLUSIVE。
7. 文件修改保存为独立本地提案，经人工批准后复制声明的源码到管理工作区，验证基础哈希后应用文本差异并运行注册命令。原目录不写回；最终合并/发布仍是单独动作。
8. Agent 的本地工具只对显式绑定目标和基线执行的任务开放；只能读该基线或自己启动的执行。Designer 能提交提案，不能调用批准接口。批准、拒绝和隔离验证结果回流到既有审批恢复协议。

## 兼容与限制

追加 runtime_context、runtime_turn、local_test_context、local_change_proposal，共 21 张业务表。沿用既有 schema.sql 的幂等新表初始化；没有修改既有列或重解释旧指标。旧运行记录仍可读，缺协议的旧未完成 Run 不冒险续写。

原来的 Budget/Loop、事件数量、工具总数和测试夹具需要随明确的新语义更新。生产权限测试继续使用真实 AgentTypeResolver；生命周期测试通过测试配置显式授权替身工具，不在生产中加入 stub 工具例外。

执行仍是本机单实例、可信操作系统用户环境，不是代码沙箱。声明的源码清单之外的工具链/依赖需要操作者纳入版本管理；网络调用在配置的连接/读取超时内返回后再核对总预算，取消不会强杀任意已进入工具函数的副作用。相关限制需随每个执行器的契约说明。
