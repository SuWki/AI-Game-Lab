# 工作台接续

## 已有游戏

在「本地游戏测试」选择已注册目标，运行后页面地址会带上执行 ID。刷新或重新打开该链接即可回到对应的日志、版本指纹和结果。

1. 在结果中导入测试计划与 Finding，打开问题详情。由本地测试导入的 Finding 提供返回来源测试的链接，方便核对原始证据与读取受版本约束的源码。
2. 生成修改提案后打开该提案。链接固定到提案 ID，可以在审批前复制链接或刷新。只有点击「批准并隔离验证」后，平台才会在独立目录执行回归。
3. 回归结束后，提案详情并列展示基线和回归的判定、失败数和证据入口。从任意一次执行可打开关联提案。对照结果用于决定下一步人工处理。

## 新作

在「游戏生产」选择任务和精确规格版本，或打开新保存的版本。制造范围确认绑定选中的版本与内容指纹。模板试做可从同一页生成项目。需要模型参与时，可创建 Builder 并进入其 Workflow 任务。

模板项目生成后，可继续执行独立验收、打包当前候选、启动限时预览以及记录候选评审。生成项目及打包完成后，地址会更新到对应记录。候选链接同时固定生产 ID 和候选 ID，刷新可回到同一个包和评审状态。预览到期后，可从该候选重新启动预览。

工作台链接保存已落库记录的定位信息。规格表单、源码编辑框和人工评审中的未保存输入仍需先提交，再刷新或离开页面。

## 验收记录

使用本地 Java 后端、隔离 SQLite 数据库和 Edge，从页面触发执行、Finding 导入、提案审批和回归。两个已有游戏沿用此前登记的源码版本和测试目标。[两条业务线基线](../reports/BUSINESS_ACCEPTANCE_2026-11-19.md)

| --- | --- | --- |
| game-demo | 18 局中错误结算 16→0，两侧均为 2 场胜利，回放检查通过。 | 原测试、Finding、待审批提案、通过回归的提案。 |
| 2048 | 长按 R 重开 2→1，方向键结果一致。 | 原测试、Finding、待审批提案、通过回归的提案。 |
| 原创样例「回廊信标」 | 从规格 r1 保存和确认，经模板生产、独立验收、固定候选，到浏览器试玩正常获胜。候选保持待人工评审。 | 规格 r1、已完成独立验收的生产、同一个固定候选。 |

在两条已有游戏流程中核对了原源码的 SHA-256，审批的修改都出现在各自的隔离目录。本轮新作使用模板生产路径，模型驱动 Builder 的供应商验收继续按独立流程执行。
