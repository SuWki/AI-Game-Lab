# Tester 产品定义

Tester 以受控执行和可追溯证据发现、复现和验证游戏问题，覆盖已有游戏与新生产的游戏。测试范围取决于实际可用的命令、引擎接口或操作观察能力，不承诺接入后就能像人一样游玩任何游戏。

## 输入与输出

输入被测版本、规格/验收范围、场景、适配能力和预算；输出执行报告、实际/预期差异、Finding、复现步骤、原始证据与未测项。新作没有失败基线也可按规格进行首次验收；首个接受版本成为后续回归基线。

逻辑测试、界面流程、性能、数值实验与体验观察分开组织。确定性场景保留种子、动作、时钟/环境；非确定性场景报告重复次数和波动。不存在观察能力时明确缺证据。

## 测试原则

测试预期来自规格，不把 HP、敌人数或战斗阶段等某一类游戏规则强加给所有类型。独立验收不能由被测修改顺带弱化；修改错误测试需单独接受，并重跑基线。测试完成与测试通过不同，未测项不得统计为通过。

自动人格只代表特定策略。Finding 数量不是质量指标，缺陷减少须结合相同范围、版本与复现条件；不凭空输出状态覆盖率。严重程度与是否阻断交付由影响和验收契约确定。

## 当前与后续

T1–T7 的模拟环境、测试计划和 Finding 已实现；本地命令接入与版本证据已有首版。独立验收保护、可移植构建、更多交互适配和新作规格覆盖是后续任务。模拟器无异常不证明真实游戏无缺陷。
