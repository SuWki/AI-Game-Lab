# Tester：跨游戏与生产验收

层级：Project。2026-11-12。T1–T7 为既有模拟测试阶段；真实命令接入已有首版，逐帧交互能力依适配器而定。新增部分为待实施，引用 [本地协议](../../platform/LOCAL_GAME_TEST_EXECUTION.md)、[可信验证](../../platform/IMPROVEMENT_VALIDATION_DESIGN.md)、[生产契约](../../platform/GAME_PRODUCTION_CONTRACT.md)。

## 接口与证据

用能力清单选择命令、交互或成品观察通道。Game Build 不恒等于 GameConfigVersion；实际执行固定 source/build/test-contract 标识。旧模拟接口保留语义，不将真实游戏硬塞为 ORBITAL 数据。任何能力未接入时明确 UNSUPPORTED/缺证据，不伪造截图或动作重放。

Invariant 必须声明适用规则；负 HP 或超过基础 MaxHP 在某游戏中可能合法，不能作为全游戏通用 bug。记录观察频率与覆盖范围，不能承诺未观察时刻“零漏报”。同 seed 重放只在随机数、时钟、动作与环境可控时承诺；其他游戏记录复现次数、样本和波动。

## Agent、工具与 Prompt

输入是冻结规格/验收、被测版本、适配能力与预算。流程为计划覆盖 → 执行场景 → 收集证据 → 上报 Finding → 总结覆盖/未测。Tester 执行独立检查与有界探索，不能通过修改实现来消除失败。

现有模拟工具为 test_plan_get、game_start、game_observe、game_act、game_collect_events、game_collect_metrics、finding_report、test_report_create。当前绑定本地目标的 TESTER 只可 local_test_start/result/import；不声称这些工具已支持逐帧游玩。工具结果的证据引用与资源范围由服务验证，Prompt 不能替代授权。

待实施：创建并冻结生产验收契约，输出需求 ID→场景→检查语义版本映射；测试执行绑定该契约。人工接受验收变更后重建基线。验证步骤复用注册命令，Tester 不开放任意 shell。Prompt 明确完成报告不等于全部场景通过，预算中断必须列未测项。

## 新作与已有游戏

新作从 GameSpec 生成启动、主循环、边界、结算与重开验收，不要求先有失败 Finding。第一个切片通过后保存回归基线。已有游戏优先复现问题，再运行候选与旧回归。生成者可补单元测试，但冻结独立验收程序由 Tester/人类负责；职责不同不自动意味着证据独立，仍须执行端保护。

Finding 保存实际/预期、需求与场景引用、版本、原始证据、复现方法；无法观察时保留未知。测试范围无异常与“游戏没有 bug”不同。当前导入状态 MANUAL 表示导入来源，不能改写成模型独立发现。

## 任务与验收

| 任务 | 前置/实现范围 | 验收 |
|---|---|---|
| T-N1 独立验收 | VAL-01；计划/证据服务 | 同 ID 改断言、恒真脚本、漏场景不能通过新标准 |
| T-N2 可移植真实目标 | ADAPT-01；执行适配 | 两个实际目标可在干净工作区测试，错误构建可识别 |
| T-N3 新作覆盖 | GameSpec 交接 | 新作无 Finding 基线也能验收；全部需求映射到自动检查或明确人工项 |
| T-N4 对照与复现 | COMP-01 | 复现率带分母，非确定性明确标注；功能退化保留证据并阻断相应接受 |

验证包括：中途取消/崩溃、缺依赖、无截图能力、存档污染、测试范围变化、功能正确但不能重开。资源有上限；30/60/120 分钟是可选场景预算，非每任务必跑。
