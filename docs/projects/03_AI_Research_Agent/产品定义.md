# Research 产品定义

Research 为已有游戏分析与同类型新作设计提供有来源的机制研究、竞品资料和技术信息。输入具体问题、目标类型/玩家/平台与时间成本范围；输出支持与反对证据、适用条件、未知项及设计建议。

## 工作方式

拆解问题 → 搜索/读取材料 → 保存出处 → 区分事实与推断 → 查反例与来源独立性 → 交付研究报告。重要结论可返回“不确定”，不以凑齐来源数量作为完成标准。Quick/Deep 表示预算选择，非必须读取 20/200 篇的指标。

官方、开发者、学术与社区来源各有用途，类别不能自动保证真实性。转载重复不等于独立证据。评分用于排序和解释，未经校准不能表述成事实为真的概率；来源日期、适用游戏版本和当前问题需匹配。

## 与其他模块协作

Designer 消费研究形成假设和差异化方案；Tester 用可实验问题设计验证；QA 查证争议。Research 不以外部资料替代当前游戏的实测，不负责修改源码或批准候选。

新作研究应总结同类机制、玩家需求、设计取舍和可变化空间，交付本作品的差异化方向。引用素材或源码需明确其来源与可用范围；研究机制不等于已取得成品资产。

## 状态与边界

R0–R2 已有搜索/抓取、来源/断言/报告与 Designer 消费能力；独立来源评估、结构化 ReferenceStudy 和网络边界硬化待完善。当前未实现通用 Python 分析执行器。每次生产不必强制调用 Research，已有明确规格可直接设计制造。
