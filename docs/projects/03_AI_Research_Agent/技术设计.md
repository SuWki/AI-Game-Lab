# Research 技术与执行设计

层级：Project。2026-11-12。R0–R2 已有实现；本页区分代码事实与新增设计，取代仅以 R0 任务树推断当前功能的做法。复用 [共享 Runtime](../../platform/AGENT_RUNTIME_RECOVERY.md) 与 [生产交付契约](../../platform/GAME_PRODUCTION_CONTRACT.md)。

## 当前实现

RESEARCH 经 DefaultAgentTypeResolver 使用研究 Prompt 与 6 个工具：web_search、fetch_page、save_source、extract_claims、compare_sources、generate_report。SerpApiSearchClient / SearchGateway 负责搜索，WebFetchService 获取正文。没有 calculate/python_analysis 已注册能力。配置/连接失败应作为失败记录，不把测试 Stub 的结果当真实搜索。

research_source 保存来源，research_claim 保存支持/反对引用与 confidence/status；报告复用 design_document。generate_report 按本 Run 查询来源/断言，同问题报告幂等；compare_sources 验证同 run/task 来源与互斥关系并事务更新。Designer 的 get_research_context/claims 消费显式关联的研究任务。现有 `/api/research/sources`、`/claims`、`/reports` 为查询入口，来源/断言详情及引用来源端点在 ResearchController。

当前 confidence 是按来源数量加减的启发式分数，不是经过校准的真实性概率。去重 ID 不等于来源独立；转载同一消息不能视为多个独立证据。报告已保存并不证明提取、归因与置信度正确。

## 新增 ReferenceStudy 设计

输入：研究问题、目标类型/玩家/平台、简报版本、来源限制、时间/费用/数量上限。输出按生产契约 envelope 保存：机制观察、适用条件、支持/反对来源、未知项、设计可借鉴原则、差异化候选。分别标明事实/推断/建议；研究可以得出“无法确定”。

来源元数据新增方向：发布时间与访问时间、材料适用版本、摘录定位、内容 hash、原始发布链/独立性分组、可用范围。先设计增量迁移与旧记录缺字段策略，不能以抓取时间冒充发布时间。冲突不由简单投票抹掉，交 Designer 选择验证假设。

## Agent / Tool / Prompt

研究循环：拆问题 → 有界搜索 → 获取原文 → 保存可核对来源 → 抽取断言 → 查反例 → 形成 ReferenceStudy。没有足够证据时允许早停；Quick/Deep 是预算配置，不要求凑满 20 或 200 个来源。

沿用六项工具的 schema 与所有权；新增来源定位/独立性先做服务校验，再扩充 schema，工具失败携带可重试类别。报告引用冻结的输入 revision。Research 无源码写权限、没有批准或发布工具。长期 Prompt 单独版本化，外部页面作为数据处理，不把页面中的命令当系统指令。

网络边界待硬化：协议/目标地址与逐跳重定向、下载与解析大小、MIME、总截止时间。受控替身测试超时、重定向和超大页面；不要以实际公网探测代替边界测试。现有实现不因此被宣称具备这些保证。

## 任务与验收

| 任务 | 依赖/修改范围 | 验收 |
|---|---|---|
| R-N1 来源可靠性 | Research 数据/抓取服务；SAFE-01 | 转载只计一个独立证据组；无日期保留未知；大响应/超时有界失败 |
| R-N2 ReferenceStudy | 生产契约元数据 | 两个互相矛盾来源均保留；事实、推断、建议可区分；旧报告可读 |
| R-N3 研究到规格 | Designer D-N2 | 机制结论引用可追溯；缺来源不能自动成为已验证需求；新作差异化建议可消费 |

验收不使用“confidence>0 就通过”。固定材料检验归因、反例、跨任务拒绝与报告幂等；真实研究另记录成本、来源质量与人工修订。Research 既服务已有游戏，也服务新作，非每次生产都强制联网研究。
