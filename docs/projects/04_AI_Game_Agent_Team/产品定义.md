# QA 团队产品定义

QA 回答“这个候选在约定范围内是否有足够证据可以交付”，并指出失败、未测与需人类评价的部分。Tester 执行检查，QA 判断覆盖和接受条件；角色数量不等于可信度。

既有游戏：核查目标问题、旧功能退化、前后对照和变更范围。新游戏：核查规格覆盖、启动至重开的可玩闭环、素材与运行说明、已知限制。无需每个任务运行完整团队，单一明确问题采用最小所需角色。

QA Lead 组织验证，玩家角色尝试特定策略，数值/战斗/漏洞角色解释各自证据，UX 角色提出待人类核对的体验观察。不存在观察权限时不能模拟看到画面；自动策略的表现不等于真实玩家满意度。

自动质量建议与人类接受分别保留。证据不足不能算通过；人工接受风险必须记录理由，也不能覆盖原始自动结果。质量通过不直接触发公开发布。

当前阶段目标是把既有模拟 Gate、本地测试评估和未来生产验收清楚展示并逐步统一引用，保留各自指标语义。非目标为“多 Agent 投票决定好玩”、以固定 build 分布判断全部类型游戏平衡、替代真实玩家反馈。
