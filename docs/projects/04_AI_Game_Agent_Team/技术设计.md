# QA 技术与执行设计

层级：Project。2026-11-12。复用 [Runtime](../../platform/AGENT_RUNTIME_RECOVERY.md)、[可信验证](../../platform/IMPROVEMENT_VALIDATION_DESIGN.md)、[生产契约](../../platform/GAME_PRODUCTION_CONTRACT.md)。

## 当前事实与历史设计修正

QaOrchestratorService 使用普通 Task/Run 和 qa_role_assignment 编排；QaReleaseGateService 与 qa_release_gate 保存门禁。角色身份 QA_LEAD/QA_TESTER/QA_ANALYST/QA_RESEARCHER 复用 Resolver 与版本化 Prompt；不新建 QA Runtime。Lead 工具包含 create/start/check/collect/complete 编排及 finding_report，具体名称/参数以现有 Tool schema 为准。

历史文件中的“没有编排/无历史回放/无执行白名单/预算耗尽成功”不代表当前代码。共享 Runtime 已更新，但 QA 编排自己的持久 deadline、累计预算与恢复仍需专项核对，不能从单 Run 修复推导整棵任务树已可靠。

Phase 3 dominantBuildShare 是实验 games 占比，在等量分组时是 1/3，不代表玩家偏好、胜场贡献或强度。已有 Gate 记录保留旧口径，任何新平衡门槛需要独立指标版本。`/api/qa/local-tests/{id}` 当前是本地结构化证据判定，不是将本地版本转换成模拟 GameConfig 后运行旧 Gate。

## 待实施：固定评估快照

评估输入固定 candidateRef、acceptanceContractRef、executionRefs、findingRefs、metricDefinitions、requiredRoles 与缺项；引用版本与 hash，不再以 latest 查询改变过去结论。版本化评估器输出 checksDecision、coverageGaps、blockingFindingIds、recommendation、reasons 和 evidenceRefs；人类决定单独保存。

结果兼容：旧 Gate 保持其枚举与解释；新生产评估明确区分 PASS、FAIL、INCONCLUSIVE，并用迁移/DTO 版本处理，不直接改旧数据库值。条件接受是人类有理由承担非阻断风险，不能吞掉未执行的必需验收。

校验覆盖、必需证据、构建身份和阻断 Finding，再评价指标目标；角色意见冲突追溯同一证据或触发有界补实验。报告必须覆盖“已测/失败/未测/人工项”，不得把 Run COMPLETED 等同于角色证据合格。

## Agent、权限与错误

Lead 获得固定评估范围、角色/费用/墙钟预算；子角色只读指定候选与证据。不得扩大目标、写游戏源码或审批制造提案。Prompt 根据证据提出理由，不生成未经观察的度量；QA 自己的意见不算游戏实测。

编排阶段状态与子 Run 状态分别显示。待实施恢复将 deadline/累计消耗持久化；取消后不得新开子任务，受管子任务按明确策略取消并记录已结束结果。补实验超过上限返回证据不足，不能无限循环。工具参数 schema、资源授权和事务边界在服务落实，Prompt 只是行为约束。

产品 API 继续扩展现有 `/api/qa` 范围，新增候选评估前先给 DTO/存储迁移方案；本设计没有宣称新路由已经存在。交付页消费同一评估快照，不复制一套判定逻辑。
