# Game Builder 产品定义

## 用户与目标

面向个人开发者与小团队，将可执行设计规格制造为实际可玩作品。用户可以说“做一款同类型、但有不同主题和成长机制的游戏”，平台先明确机制、范围与差异，再生成可审查的实现。也可承接已有游戏的新功能或修复。

目标产出是有源码、构建、操作说明和验收证据的候选游戏。“同类型”允许共用工程模板与机制范式，每个作品有独立规格、资产和版本，不以更换名称颜色作为完整设计差异。

## 第一版范围

第一生产模板选择单机 2D Web 游戏。2026-11-13 已先交付零依赖 Canvas / ES modules 的短局生存切片，以验证规格到可玩产物；Phaser + TypeScript + Vite 保留为后续模板路线。依赖版本在各模板建立时锁定验证。先做从开始到胜负、重开的一个完整可玩切片，再增加成长/关卡内容。

每次明确范围：一个核心循环、有限输入方式、明确结算、可验证的差异机制、占位或可用素材、目标浏览器和运行说明。联网、支付、复杂编辑器、多引擎与无限量内容生产不纳入第一版。

## 用户流程

简报 → 可选参考研究 → 确认规格与范围 → 可玩切片 → 反馈与迭代 → 独立测试/QA → 候选交付。规格确认可在任务开始时一次授权明确范围；需要扩大范围、引入未确定素材或降低验收时再交给用户决定，避免每个内部步骤都要点击批准。

改进现有游戏沿用基线与提案审批；新建游戏使用独立输出目录，验收不要求存在旧失败版本。平台展示进度、可玩预览、差异、失败原因和剩余问题。遇到不可能的目标时交付缩减建议与已完成部分。

## 完成定义

接受范围内的玩法可运行；可开始、交互、结束并重新开始；构建与实际运行一致；必需自动检查通过；人类完成视觉/体验评审；源码与依赖、产物、素材来源、测试报告、已知问题齐全。候选交付不等于自动发布，更不保证商业成功。

首轮用同一模板产生两件规格不同的可玩作品，至少一项核心规则或成长系统差异，记录人工干预、返工原因、成本和完成时间。既检验重复生产，也检验复用是否降低工作量。
