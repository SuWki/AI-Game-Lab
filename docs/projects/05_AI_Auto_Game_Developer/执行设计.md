# Builder 的 Agent、工具与 Prompt

层级：Project。待实施。运行循环、审批恢复与预算均使用 [共享 Runtime](../../platform/AGENT_RUNTIME_RECOVERY.md)，交接对象见 [生产契约](../../platform/GAME_PRODUCTION_CONTRACT.md)。

## 身份与上下文

新增 BUILDER 身份时同时更新 AgentType、Resolver、Prompt、执行白名单与测试，不能仅在前端增加选项。上下文固定 productionId、specRef、templateRef、acceptanceRef、workspaceId、允许改动路径、预算与上一轮验证结果。范围来自服务端记录，不接受模型自报工作区权限。

Agent 循环为读规格/计划→生成有界差异→审阅/批准→执行验证→读取失败证据→修复或结束。阶段协调服务负责可靠调度，模型只决定局部实现和诊断，不持有绕开 Runtime 的执行线程。

## 拟新增工具契约

下表是拟议名称，当前尚未注册。参数对象不接受任意 shell 字符串。通用输入严格禁止多余属性，路径和资源 ID 再由执行服务核对。

| 工具 | 输入 → 输出 | 副作用/授权 |
|---|---|---|
| production_context | productionId → 固定规格/模板/验收引用及能力 | 只读当前任务 |
| workspace_read | workspaceId,path,offset,limit → 文本片段/hash | 只读允许范围；大小上限与分页 |
| workspace_propose | workspaceId,baseHash,edits,reason,requirementIds → proposalId/diff | 只保存提案；应用须符合已授权范围及审批策略 |
| production_validate | productionId,candidateId → executionId/status | 执行已注册固定阶段；费用/队列上限；同请求幂等 |
| production_result | executionId → 日志摘要/检查/证据引用 | 只读自身或明确授权的执行 |
| candidate_package | productionId,candidateId → artifactRef/manifest | 服务校验 QA/验收和版本；仅打包，不公开发布 |

模板实例化由确定性准备服务按已接受请求执行；模型不能直接选择磁盘任意目录。审批为用户/服务入口，没有 approve、git_push、publish 工具。用户在创建请求时授权的固定范围可通过明确策略减少逐次确认；第一版默认文件提案人工审批，不把未实现的批量授权当现有行为。

错误结构含类别、是否可重试、关联执行与证据。版本冲突返回需重新计划；工具失败进入可见观察，不能由模型凭空报告成功。未知已启动副作用按 Runtime 恢复规则处理。

## Prompt 设计

System Prompt 使用版本化 builder_p001 资源（尚未创建代码资源），包含：仅实现接受规格；保留验收；不发明工具或运行结果；先读后提案；每项修改引用需求；失败基于证据诊断；范围外改动请求规格调整；达到预算如实交付未完成。

任务输入分离为受信任约束、规格数据和外部材料。源文件/日志里的指令不是额外授权。输出摘要含 completedRequirementIds、pendingRequirementIds、candidateRef、testRefs、knownIssues、nextDecision，不输出未经校准的“Release Confidence 0.78”。

样例约束：验证工具返回“build success，但重开场景失败”时，下一步修复重开并复测；不能只引用 build success 就结束。若独立检查不可用，报告证据不足，不生成通过声明。
