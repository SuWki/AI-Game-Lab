# 平台设计与代码审查 · 2026-11-19

审查基线为 `164f09a`。建议保留“改进已有游戏”和“制造同类型新作”两条线。两者都需要明确目标、固定版本、可重复执行的测试，以及一次能追溯到证据的接受或拒绝。共享 Java 运行时、SQLite 和审批工作区已经能承载这些操作。下一轮开发的价值在于让用户判断哪一版满足了哪项目标。

## 五个模块能交付什么

| 模块 | 当前可用 | 阻碍用户完成任务的缺口 |
| --- | --- | --- |
| Research | 搜索、抓取、保存 Source/Claim，供设计任务引用 | 自动抓取的目标范围和下载体积缺少执行约束。第三方游戏可使用有来源的公开材料开展分析，资料中的判断仍需实测。 |
| Designer | 可根据证据提案，人工可在生产页保存和修订有版本的 GameSpec | 模型报告尚不能直接交接为可审阅的规格。保存草案、同意投入制造、接受最终作品是三个不同的业务决定。 |
| Builder | 可消费精确规格，用 survival-web 构建两种机制，运行有预算的修复流程并冻结候选 ZIP | 验收准备中断后的恢复有缺口。两种模板选项已有实现，两款作品分别经试玩交付的 B-07 验收仍待完成。 |
| Tester | 已有游戏支持注册测试、固定版本、导入 Finding 和隔离回归。生产模板另有独立引擎检查 | 普通注册目标的验收强度取决于其适配器。固定候选还缺按规格编号回传的浏览器证据。 |
| QA | 模拟实验有角色和发布判定，本地游戏有证据评估，固定候选支持逐项人工观察、接受、拒绝和历史回执 | 三类结论的适用范围不同。旧模拟判定的实验选择影响可解释性，候选人工观察也不能充当自动实测。 |

一个实际分歧说明了为什么值得保留这套平台：已有验收中，热量机制在重开首帧显示 6，与该候选要求的 0 不符。平台可以保留被拒绝的固定包和原始规格，下一版只需证明同一观察点是否改变。以此验收 Tester 和 QA，比再生成一个看似可玩的页面更能说明产品价值。[既有试玩记录](SELF_ACCEPTANCE_2026-11-17.md)

## 按影响排序的代码发现

以下为当前版本的源码审查。P1 表示应优先于扩大使用范围或依赖该能力的下一阶段，P2 表示影响可靠性、追溯或规模。网络影响取决于实际监听、代理、防火墙和执行账户权限。本轮没有对外部服务或内网目标执行安全探测。

| 优先级 | 证据、触发条件及影响 | 建议与关闭条件 |
| --- | --- | --- |
| P1 · 本地访问边界 | 默认后端配置只指定端口。部分写入口检查回环来源，通用配置审批和本地源码读取入口没有相同检查。若其他机器能到达后端，操作记录和游戏源码的可见范围可能超过单人工作台的设计。无法据此判断某台电脑已经对外开放。[默认配置](../../backend/src/main/resources/application.yml) · [本地测试入口](../../backend/src/main/java/com/aigamelab/api/LocalTestController.java) · [配置审批入口](../../backend/src/main/java/com/aigamelab/api/ConfigController.java) | 默认绑定回环，核对 Vite 代理和本地客户端；梳理敏感读写入口的一致访问策略。验收包含正常本地流程、非本地请求拒绝和 Pages 无后端调用。 |
| P1 · Research 网络与内存 | 抓取服务使用输入 URL、自动跟随跳转，缺少目标网络范围校验。响应先完整读入字符串并解析，8000 字符上限仅约束最终文本。自动研究可能触及不属于研究范围的服务，大响应会占用与其他 Agent 共享的 JVM 内存。[WebFetchService](../../backend/src/main/java/com/aigamelab/research/WebFetchService.java) | 对实际连接目标及每次跳转执行同一出站策略，限制跳数、读取字节、时限和可接受的内容类型。用受控传输夹具验证普通网页成功、受限目标和超限响应明确失败。 |
| P1 · 独立验收无法原任务重试 | 首次验收先独占创建契约文件，再保存其指纹。如果在两步之间中断，重启后数据库仍无指纹，重试又要求同名文件必须不存在。构造器只恢复未关联执行的初始构建，无法处理此时已构建的任务。该窗口由代码顺序确认，未做进程故障注入。[ProductionJobService.validate](../../backend/src/main/java/com/aigamelab/production/ProductionJobService.java) | 持久化待准备状态和预期指纹，幂等核对文件；一致时续办，不一致时记录冲突。对文件写入前后、执行关联前后的中断分别验收，确保同一任务至多采用一份有效基线。 |
| P2 · 模拟 QA 的证据选择 | 评估按配置和场景选最新完成的实验，推导最大流派局数占总局数的比例，返回单个数值。同一配置新增实验后，重新评估可能使用另一批样本。该比例描述样本分布，无法单独回答“哪种玩法更容易赢”。[实验选择](../../backend/src/main/java/com/aigamelab/qa/QaBuildShareDeriver.java) · [判定规则](../../backend/src/main/java/com/aigamelab/qa/QaReleaseGateService.java) | 新版判定保存实验 ID、规则版本、样本数和结果引用；将样本分布与玩法胜率分别展示。两个同配置实验可分别回放，旧判定仍按原规则解释。 |
| P2 · 查看生产列表产生写入 | 列表对最近最多 100 个任务逐一调用详情。已关联构建或验收的任务即使状态未变，详情仍保存整条记录；生产页有活动任务时每秒轮询整个列表。单连接 SQLite 同时还要服务审批和 Run。源码确认有重复写，尚未测量用户可察觉的延迟。[生产服务](../../backend/src/main/java/com/aigamelab/production/ProductionJobService.java) · [页面轮询](../../frontend/src/pages/ProductionsPage.tsx) | 列表读取轻量摘要，状态变化时才持久化。用一项活动任务加一批历史任务验证终态零重复写，并对照审批延迟后再决定是否需要换数据库。 |

## 范围与验收

本轮对照五模块设计、生产页、服务端入口、生产与评审服务、研究抓取、模拟 QA、相关回归测试和既有试玩报告。上述发现包含源码确认的问题和带前提的部署风险，未做逐文件穷举、依赖漏洞库扫描或真实模型付费验收。各项修复和可重跑的退出条件见[当前路线](../design/DEVELOPMENT_ROADMAP.md)，实现状态以[进度记录](../state/task-state.md)为准。
