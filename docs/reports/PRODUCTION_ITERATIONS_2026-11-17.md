# 生产修复链交付记录

2026-11-17，基于 main `4f1de9f`，B-05 首个实现切片。[协议与剩余工作](../platform/PRODUCTION_ITERATIONS.md)。

## 本轮能力

生产记录与既有源码提案/执行形成同一条修复链。读取、提交和页面入口跟随当前候选；失败回归可继续修复，不再每轮退回最初源码。通用提案入口也执行当前候选、未决提案和最多五次的限制；拒绝和失败不清零，非法提交不占次数。

`iteration` 返回阶段、原因、次数、当前执行/判定/检查、候选目录及提案摘要。构建 BUILT、引擎 REVIEW 和人类接受继续分开。新候选证据不足或执行中断不会被初始 PASS 掩盖。生产页区分初始项目与当前候选，并保留逐轮回归链接。

取消与子执行注册使用同一策略锁：取消标记先持久化，已登记执行停止，待批提案和准备后尚未登记的回归不能再启动；已停止的拥有者 Agent 也不能留下可继续批准的待决提案。提案创建在事务内检查并保存，两个并发提交只有一个成功。读投影不持该锁，避免与单连接事务形成锁顺序死锁。

沿用 23 表、40 工具和 15 Prompt。没有新 AgentLoop 或工具 schema；历史冻结 Prompt 保留，工具观察提供当前检查。

- 后端全量 722 项通过；最终阶段归类和审批后候选读取补充后，21 项生产/Builder 定向测试通过。
- 前端构建及 72 项测试通过，包括待批提案取消入口和当前候选链接。
- 新增后端测试覆盖五次失败链/第六次拒绝、旧基线拒绝、拒绝仍计数、通过进入 REVIEW、并发唯一提交、取消/停止 Agent 后审批拒绝、候选证据不足不得冒用原始 PASS。从新服务实例读取相同数据库仍恢复同样链状态。
- CheckingGateway 读取真实工具观察，审批后再次 production_source_read 得到候选的新 hash；使用实际 Node 构建/验收，不代表真实模型供应商验收。
- 本地真实 Edge/API：初始 PASS → 刻意注入移动故障的提案回归 FAIL → 在失败候选上提出第二轮修复 → 审批后 PASS/REVIEW。原项目未改，页面显示两轮状态与候选目录。见 [机器记录](evidence/iterations-2026-11-17/workflow.json)、[页面截图](evidence/iterations-2026-11-17/repair-chain.png)。故障为验证夹具，不声称模型发现了真实缺陷。
- 对同类成功生产重启后端：完整 iteration 对象与全部既有执行 ID 保持一致，未重放构建/回归。见 [重启记录](evidence/iterations-2026-11-17/restart.json)，记录中的 productionId 标识该次重启样本。
